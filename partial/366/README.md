# Erdős Problem #366 — partial results

**Problem** ([erdosproblems.com/366](https://www.erdosproblems.com/366)). Is there a positive integer n such that every prime dividing n divides it at least twice (n is 2-full, or powerful), while every prime dividing n + 1 divides it at least three times (n + 1 is 3-full)? The reverse pattern exists: 8 = 2³ is 3-full and 9 = 3² is 2-full. **Prize:** none on erdosproblems.com. The formal statement `Erdos366.erdos_366` (`∃ n > 0, (2).Full n ∧ (3).Full (n + 1)`, google-deepmind/formal-conjectures) matches the problem exactly and is a live conjectures.io bounty target.

**Status of the problem** (as of 2026-11-25): open. Erdős and Graham asked whether (8, 9) is the only pair with n 3-full and n + 1 2-full; Golomb (1970) already knew a second, 12167 = 23³ and 12168 = 2³·3²·13². For the direction asked here, no example is known; the OEIS A060355 list of consecutive powerful pairs covers n < 10²² and contains none. Erdős (1976) also asked for two consecutive 3-full numbers (Guy, B16), which would give a "yes" here.

## Results here

1. **[Computed]** *No solution with n < 10²⁴* (exhaustive; independent of the OEIS list). Every 3-full m ≤ 10²⁴ is enumerated exactly once as m = a³b⁴c⁵ (b, c squarefree and coprime), and m − 1 is tested for being 2-full by the test in item 2. 460,160,083 3-full numbers were checked (trial primes up to 63,097). As a built-in control the same run tests m + 1 and must find the reverse pairs: it finds exactly m = 8 and m = 12167, and nothing else, up to 10²⁴. Cross-checked against sympy factorisation for N = 10⁶ (same 307 cube-full numbers, same outputs). C with OpenMP, 2 cores, 128-bit arithmetic.
2. **[Proved]** *Exact 2-full test without factorisation.* If B⁵ ≥ x (it suffices that (B+1)⁵ > x), strip every prime p ≤ B from x; x is 2-full iff no stripped prime divides x exactly once and the leftover r is 1, a square or a cube. Reason: r has all prime factors > B and r < B⁵, so r has at most 4 prime factors with multiplicity, and the 2-full options (p², p³, p⁴, p²q²) are all squares or cubes. B⁵ is tight (p⁵ and p²q³ would be missed at 5 factors). Checked by an independent referee against factorisation for all x ≤ 3·10⁵ and 3000 structured random cases, 0 mismatches.
3. **[Reduction]** *Each "shape" is one elliptic curve.* Every 2-full n is uniquely a²b³ (b squarefree) and every 3-full m uniquely Kc³ with K = d⁴e⁵ (d, e squarefree, coprime). For fixed (b, K), the solutions a²b³ + 1 = Kc³ correspond exactly to integral points (X, Y), Y > 0, on Y² = X³ − K²b³ with Kb | X and Kb³ | Y, via X = Kbc, Y = Kb³a. So the problem splits into infinitely many Mordell curves, each with finitely many integral points (Siegel), and each solution lies on exactly one curve. Verified symbolically by the referee.
4. **[Computed]** *No solution of any size with b ≤ 100 and K ≤ 3888,* except possibly on 16 curves listed below. For all 61 squarefree b ≤ 100 and the 11 values K ∈ {1, 16, 32, 81, 243, 625, 1296, 2401, 2592, 3125, 3888} (every d⁴e⁵ ≤ 3888), the integral points of the 671 curves were computed rigorously (Sage `integral_points`: Mordell–Weil basis plus Baker-type bounds). 618 curves were certified directly; 37 more after PARI `ellrank` proved rank 0. None gives a solution. Control: the reverse equation (curves Y² = X³ + K²b³) recovers exactly 8 and 12167 for b ≤ 3, K = 1. **Not covered:** (b, K) = (97, 243), (73, 625), (97, 625), (43, 1296), (67, 1296), (78, 1296), (82, 1296), (93, 2401), (69, 2592), (94, 2592), (97, 2592), (62, 3125), (77, 3125), (46, 3888), (70, 3888), (94, 3888), where the rank is 1 or 2 but no generator was found. In words: if a solution exists, then either n's squarefree "cube part" b exceeds 100, or n + 1 has a prime to the 4th or 5th power beyond the small list above, or it lies on one of these 16 curves. Within the grid this holds for every size of n, not just below 10²⁴.
5. **[Proved]** *n and n + 1 cannot both be perfect powers.* By Mihăilescu's theorem the only consecutive perfect powers are 8 and 9, and 9 is not 3-full. (Most 2-full and 3-full numbers are not perfect powers, so this excludes little.)
6. **[Proved]** *Polynomial analogue: no solutions.* Over ℂ[t] there is no nonconstant f with f 2-full and f + 1 3-full: Mason–Stothers gives deg f ≤ deg rad(f(f+1)) − 1 ≤ (1/2 + 1/3) deg f − 1, impossible.
7. **[Proved]** *Fake world where the answer is yes.* Over F₃[t], f = t⁶ is 2-full and f + 1 = (t² + 1)³ is 3-full (t² + 1 is irreducible over F₃; the same works over F_p for odd p, since t^{2p} + 1 = (t² + 1)^p). Mason–Stothers fails there because f' = 0. So any argument that is valid over F₃[t] cannot prove "no" over the integers: a proof must use characteristic 0, the way the derivative does for polynomials.
8. **[Heuristic]** *A solution above 10²⁴ is very unlikely.* Treating "n is 2-full" and "n + 1 is 3-full" as independent apart from local (p-adic) correlations, the expected number of solutions with n > X is C·c₂·c₃·X^(−1/6), with c₂ = ζ(3/2)/ζ(3) ≈ 2.173, c₃ = ∏(1 + p^(−4/3) + p^(−5/3)) ≈ 4.65 and local factor C ≈ 0.83 (computed from the true local densities of 2-full and 3-full numbers; the referee caught that a naive uniform local model gives 0.64 and is refuted by data at p = 2). This gives about 0.0018 expected solutions above 10²² and 0.0008 above 10²⁴. The answer to the problem is very likely "no".
9. **[Reduction]** *abc gives finiteness only.* rad(n(n+1)) < (n+1)^{5/6}, so (1, n, n+1) has abc quality above 6/5, and abc implies finitely many solutions. Finiteness does not decide existence, and the best unconditional effective abc bound (Stewart–Yu: log c ≪ rad^{1/3}(log rad)³) gives no constraint at all here.

## Kernel card

1. **Kernel, in plain terms.** Show there is no solution outside the region already excluded: no n > 10²⁴, and no shape (b, K) outside the certified grid, with a²b³ + 1 = Kc³. [Certain] This is not a real shrink. Given items 1 and 4 the kernel is equivalent to the original problem, so it is a renaming with a smaller search space, not an easier statement. Original implies kernel trivially (core).
2. **Missing primitive.** A uniform, effective lower bound for |Kc³ − b³a²| that holds across all shapes at once: concretely, an effective polynomial abc-type inequality n + 1 < κ·rad(n(n+1))^{6/5 − δ} for n 2-full and n + 1 3-full, with κ small enough that what remains is below 10²⁴. Per-shape tools (Baker, Siegel, the Sage computation above) supply this for one curve at a time, at a cost that grows with the size of K²b³; nothing supplies it uniformly. It must fail in the F₃[t] fake (item 7).
3. **Required ingredients.** Multiplicative: the 2-full and 3-full shapes (a²b³, c³d⁴e⁵). Additive: the single relation "+1". They interact only in the one equation a²b³ + 1 = Kc³, and the proof must use characteristic 0 at exactly that step (item 7).
4. **Suppliers.** (a) Baker's method on linear forms in logarithms: works per curve; its bounds depend on the curve's height, so it is not uniform. (b) The modular method (Frey curves, as for generalized Fermat equations): needs a fixed large prime exponent, which this problem lacks, since the exponents here are 2 and 3 with varying coefficients. (c) Unconditional effective abc (Stewart–Yu and successors): subexponential, far from the polynomial strength needed. Cheap test of (c): with rad ≈ c^{5/6}, Stewart–Yu reads log c ≪ c^{5/18}(log c)³, which every c satisfies, so it gives no bound at all. Cheap test of (a): the 671-curve computation above, where per-shape bounds succeed and the cost rises with K²b³ (16 curves already need generators that 2-descent could not find).
5. **Dial.** The exponent κ in an effective inequality c ≤ C·rad^κ restricted to these shapes. The theorem needs κ < 6/5 with an explicit constant. Today κ = ∞ (only subexponential bounds are known).

## Routes tried and why they failed
- Finite search — cannot prove "no": it is a qualitative wall, and item 8 predicts nothing will be found.
- Shape-by-shape elliptic curves — cost wall per curve, qualitative wall overall: infinitely many curves, no uniformity.
- abc — gives finiteness only, and is not effective.
- Perfect-power special case — settled by Mihăilescu (item 5), but it covers a negligible part of the problem.

## Code
- `search366.c`: exhaustive search. Build: `gcc -O3 -fopenmp -o search366 search366.c -lm`; run: `./search366 24` (the argument is the exponent of 10). Logs: `run_1e24.log`.
- `brute.py`: sympy cross-check for N = 10⁶.
- `shapes.py`: integral points on the shape curves (needs Sage; the passagemath pip packages work). Run: `python3 shapes.py 100 1,16,32,81,243,625,1296,2401,2592,3125,3888 -1 0 1`. Log: `shapes_b100.log`.
- `retry.py`: PARI `ellrank` retry for curves where mwrank could not certify a basis. Log: `retry.log`.
